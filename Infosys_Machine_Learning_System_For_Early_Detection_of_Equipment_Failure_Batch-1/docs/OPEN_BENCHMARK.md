# Flash Crash Watchdog — Open Benchmark Specification

Strategic moat (STR-12): a reproducible, pre-registered evaluation protocol that
anyone can run against the same public data. This is what turns the detector from
"claims" into a defensible open research benchmark.

Everything below maps 1:1 to a script that already exists in the repo.

## 1. Task

**Early-warning flash-crash detection** on Binance spot limit-order-book data:
given a streaming tick feed, fire alerts that (a) catch a subsequent ≥2%-in-60s
mid-price decline and (b) do so BEFORE the trough (positive lead time), while
staying quiet on calm days.

Input: per-tick depth + trades (real LOB microstructure). Output: alert timestamps
+ scores.

## 2. Dataset

Public Binance data (`data.binance.vision`), fixed day catalog
(`data/manifest.yml`, generated by `scripts/data_manifest.py`). Held-out split is
day-level and **disjoint** (enforced by `scripts/audit_dataset_split.py`):

- **Train:** LUNA-0511, LUNA-0512, ETH-0519, BTC-0518, BTC-0520, BTC-0115
- **Held-out validation:** BTC-0519, LUNA-0510, LUNA-0509, ETH-0613,
  ETH-0805, BTC-0116 (6 days)

Leakage is gated on multiple axes (`ml/tests/test_leakage.py`): leave-one-out
stage-1 z, causal batch scores, future-only labels, past-only rolling-z, and the
replay index.

## 3. Ground-truth labels

**Event-based** (`ml/flash_crash_watchdog/data/labels.py`, RSR-03): one label per
peak-to-trough descent (≥2% drop within a 60s window, recovery-gated). This
replaced the old chain-split that yielded 507 "crashes" for one day.

**Wall-clock lookahead** (`windows.py`, RSR-02): labels are defined over the next
`lookahead_ms` of *time*, not a fixed tick count — critical because real Binance
tick rates vary 8–42/s.

## 4. Normalization

One shared rolling-z (`models.stage3_tcn.normalize_z`, window500, ddof1) is used
by every offline evaluator AND the online `Stage3TCN.feed` path (BUG-03), so
offline scores transfer to live (validated by `ml/tests/test_normalization.py`).

## 5. Matching & metrics (canonical, exact)

`eval/metrics.py::match_alerts_to_crashes`:
alert matches an event iff `start - grace(5s) <= alert <= end`; one TP per event
(earliest alert); everything else FP. Reported per day + aggregated:
precision, recall, F1, **lead-time p50/p95** (STR-02), and **recall Wilson CI**
(RSR-12) — honest because event counts are n=2–9/day.

Threshold selection is **banned on the evaluation day** (`--calibrate-on`,
RSR-11).

## 6. Baselines

- **Naive price-baseline**: alert the moment the mid has already dropped ≥2%
  (post-hoc, no warning).
- **TradingView-style threshold**: alert on a raw LOB-imbalance or a fixed
  velocity threshold (included as the "baseline" comparator in
  `scripts/backtest_windows.py`, `generate_plots.py`).

## 7. Reproduction

```
PYTHONPATH=ml python scripts/run_validation.py \
    --config configs/operating.yml --models-dir models --data-dir data/parquet \
    --out results/validation.json
```
Deterministic (RSR-14 golden in `results/golden_metrics.json`); dataset-split
audit (GAP-01) and provenance audit (RSR-16) must pass.

## 8. Leaderboard criteria

Entries: model + scores. Ranked by held-out mean F1 over the 6 validation days,
with recall CI not crossing the naive baseline's recall; lead-time p50 as a
secondary tiebreak. Pre-registered: no threshold/feature selection on the eval
days.

## 9. Paper seed (outline)

1. The flash-crash early-warning gap (TradingView/Cryptohopper alert post-hoc).
2. Data + leak-proof labeling (RSR-02/03) + evaluation protocol (this doc).
3. The 5-stage cascade; Stage-4 = validated correlation-breakdown.
4. Results on the 6-day held-out set (with CIs + lead-time).
5. The anti-spam guarantee (zero calm-day alerts at the trailing-vol gate).
6. Reproducibility (Docker/CI, `run_validation.py`, golden metrics).

This makes the repo an honest benchmark others can cite, not a black-box claim.
